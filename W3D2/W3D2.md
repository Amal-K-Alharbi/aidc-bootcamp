# W3D2 — Inference Anatomy

## Prediction Card

* Longer prompt → **TTFT goes up**
* TPOT depends mostly on **model size and memory bandwidth**
* KV cache → **28 KB/token**
* 4096 tokens → **≈ 0.112 GB KV cache**
* Static batching → batch finishes when the **longest request** finishes

# Extra W3D2 — Paged KV Allocator

## Prediction Card

* Average unused slab space → **≈ 93%**
* 300 tokens → **19 blocks**
* 4096 tokens → **256 blocks**

## KV Cost

```text
28 KB/token
16 tokens/block
448 KB/block
```

## Allocators

### Slab

Reserves the maximum context for every sequence:

```text
4096 × 28 KB = 114,688 KB per sequence
```

### Block Pool

Starts with one block and adds blocks only when the sequence grows.

```text
16 tokens/block
```

## Memory Budget

```text
2 GB
```

Both allocators use the same budget.

## Result

The slab allocator wastes memory because it reserves space for the maximum length.

The block-pool allocator uses memory according to the actual sequence length, allowing more sequences to fit in the same memory budget.


## Verification

```text

```

## Key Takeaway

```text
Slab:
reserve maximum memory

Block Pool:
allocate memory as needed
```

This shows why **paged KV-cache allocation** can support higher concurrency without increasing GPU memory.
