# Lab W3D1 — Profile Inference on a Real GPU

## Overview

In this lab, we profiled **Qwen2.5-1.5B-Instruct** on a real **NVIDIA Tesla T4 GPU** using Hugging Face Transformers.

The goal was to understand how **GPU memory (VRAM)** and **GPU utilization** behave during inference, and to compare FP16 and INT8 under different context lengths.

The lab also demonstrated why **high GPU utilization does not necessarily mean high inference throughput**.

---

## Environment

* **GPU:** NVIDIA Tesla T4
* **VRAM:** 15,360 MiB (~15 GB)
* **Model:** `Qwen/Qwen2.5-1.5B-Instruct`
* **Framework:** Hugging Face Transformers
* **Quantization:** bitsandbytes INT8
* **FP16:** `torch.float16`
* **Batch size:** 1 and 8
* **Generated tokens:** 128
* **Context lengths:** 512, 2048, 4096

### Packages

* `transformers==4.46.*`
* `accelerate==1.1.*`
* `bitsandbytes==0.49.2`

vLLM was intentionally **not installed** because W3D1 focuses on direct model profiling with Transformers rather than model serving.

---

## 1. FP16 and INT8 Profiling

The model was loaded twice using different data types:

* **FP16** — approximately 2 bytes per parameter
* **INT8** — approximately 1 byte per parameter

Each dtype was tested at three context lengths.

### Results

| Dtype | Context | VRAM (GB) | GPU Utilization (%) | Tokens/s |
| ----- | ------: | --------: | ------------------: | -------: |
| FP16  |     512 |     3.113 |                58.7 |     26.5 |
| FP16  |    2048 |     3.295 |                68.0 |     28.1 |
| FP16  |    4096 |     3.568 |                91.3 |     26.7 |
| INT8  |     512 |     1.805 |                23.6 |      5.8 |
| INT8  |    2048 |     2.035 |                27.8 |      5.7 |
| INT8  |    4096 |     2.309 |                31.2 |      5.3 |

---

## 2. Effect of Context Length

Increasing the context length increased resident VRAM for both FP16 and INT8.

### FP16

```text
512   → 3.113 GB
2048  → 3.295 GB
4096  → 3.568 GB
```

### INT8

```text
512   → 1.805 GB
2048  → 2.035 GB
4096  → 2.309 GB
```

This shows that the model's memory usage is not only determined by its weights.

As the context grows, the **KV cache** also grows, increasing the memory required for inference.

---

## 3. Effect of Quantization

INT8 significantly reduced VRAM usage compared with FP16.

At context 4096:

```text
FP16: 3.568 GB
INT8: 2.309 GB
```

So INT8 used substantially less GPU memory.

However, in this experiment INT8 did **not** provide higher throughput:

```text
FP16 @ 4096: 26.7 tokens/s
INT8 @ 4096:  5.3 tokens/s
```

This demonstrates an important infrastructure concept:

> Quantization can reduce memory usage without automatically making inference faster.

---

## 4. GPU Utilization vs. Throughput

The second experiment compared batch size 1 and batch size 8 using FP16 with a 512-token context.

### Results

| Batch | VRAM (GB) | GPU Utilization (%) | Tokens/s |
| ----: | --------: | ------------------: | -------: |
|     1 |     3.113 |                52.0 |     26.3 |
|     8 |     3.527 |                70.0 |    186.3 |

The throughput increased from:

```text
26.3 → 186.3 tokens/s
```

which is approximately:

```text
7.08×
```

However, GPU utilization increased only from:

```text
52% → 70%
```

an increase of:

```text
18 percentage points
```

The ratio-of-ratios was approximately:

```text
5.26×
```

This demonstrates that GPU utilization and useful inference throughput are **not the same metric**.

A GPU can report high utilization while the workload is not necessarily achieving maximum useful throughput.

---

## 5. Key Lessons

### VRAM

Model weights are only part of inference memory.

```text
VRAM =
Weights
+ KV Cache
+ Activations
+ Runtime / CUDA overhead
```

Longer contexts increase the KV cache and therefore increase VRAM usage.

### Quantization

INT8 reduced memory consumption significantly, but lower memory usage did not automatically result in higher throughput.

### GPU Utilization

`nvidia-smi` GPU utilization indicates that the GPU was doing work during sampled intervals.

It does **not** directly measure:

* inference efficiency
* useful throughput
* tokens generated per second
* GPU saturation

Therefore:

> **"The GPU is busy" does not necessarily mean "the GPU is working efficiently."**

### Batching

Increasing the batch size allowed the GPU to process more work in parallel.

This resulted in a large throughput improvement while GPU utilization increased much less dramatically.
