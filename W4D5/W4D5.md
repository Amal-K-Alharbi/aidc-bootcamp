## Go-Live Overview

The W4D5 go-live focused on preparing the model-serving system for real external use. The team secured the API, exposed the service outside the cluster, verified it from an external client, enabled monitoring, prepared the integration documentation, completed the acceptance process, and started the uptime watch.

Each team member contributed to a different stage of the go-live process.

## Go-Live Steps

### Step 1 — API Key & Security

A Kubernetes Secret was created to store the API key. The serving API was configured to require authentication for the `/v1` endpoints while keeping `/health` accessible for health monitoring.

### Step 2 — Metrics & Monitoring

Prometheus was configured for serving monitoring. The team verified that serving metrics were available and that metrics history was being recorded.

### Step 3 — External Exposure

The model-serving endpoint was exposed outside the cluster through the team's public endpoint:

`https://t10.aidc.nadir.sh`

### Step 4 — Outside-In Smoke Test

The endpoint was tested from outside the cluster to verify:

* `/health` accessibility
* API authentication
* `/v1/models` availability
* Model ID
* Chat completion functionality

### Step 5 — Integration Note

The team prepared the integration note for the Agentic AI team. It documents the endpoint, model, authentication requirements, API examples, and expected service behavior.

### Step 6 — Acceptance Review

The integration note was exchanged and tested according to the acceptance requirements. The reviewer tested the documented API calls and checked the authentication and service expectations.

Each team member participated in the review and verification process.

### Step 7 — Uptime Watch

The public endpoint was submitted to the instructor's uptime watch. The `/health` endpoint was monitored periodically to build uptime history for the capstone evidence.

### Step 8 — Final Verification

The complete outside-in serving posture was verified using `verify.sh`.

The verification confirmed that the public endpoint was reachable, the model was being served, and the monitoring history was available.
